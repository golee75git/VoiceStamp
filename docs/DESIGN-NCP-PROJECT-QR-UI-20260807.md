## 1. 목표·원칙

### 1.1 UX 목표

| ID | 목표 |
|----|------|
| U1 | 촬영자는 **QR 한 번** 이후 저장만 하면 된다 (ZIP·공유 불필요) |
| U2 | 관리자는 **사업 만들기 → QR 보여주기 → 수신·내 폰으로 가져오기** |
| U3 | 기본값은 **미연결·업로드 없음** (opt-in) |
| U4 | 기존 `MainScreen` 화면 전환(`camera \| list \| settings \| …`) 패턴 유지 — React Navigation 추가 없음 |
| U5 | 클라우드 실패해도 **로컬 저장은 성공** (갤러리 백업과 동일 톤) |
| U6 | 수신 「내 폰으로」시 **사업 폴더**로 자동 분류 (`groupName`) |
| U7 | 수신함·목록에서 **해당 사업분 엑셀 일괄 보내기** (기존 XLSX 파이프라인) |
| U8 | 엑셀은 **누적 append가 아님** — 로컬에 모인 선택분으로 **새 XLSX** 생성 |

### 1.2 UI에서 쓰지 않는 표현

- 「동기화」「백업」「클라우드 드라이브」→ 사용자 카피는 **「사업에 올리기」「일시 보관」「수신」**
- 「서버」「NCP」「Firebase」→ 설정 고급/도움말에만, 본문 UI는 **「일시 저장소(한국)」**

## 3. 정보 구조 (IA)

```text
설정
 └─ 사업 취합
     ├─ (미연결) 「시작하기」→ S1
     ├─ (촬영자 연결됨) 사업명 · 끊기 · 대기 N건
     └─ (관리자 사업 있음) QR 보기 · 수신 · 종료

S1 사업 허브
 ├─ 사업 만들기 (관리자) → S2 → S3
 ├─ QR로 참여 (촬영자) → S4
 └─ 수신 목록 (관리자) → S5
```

한 기기가 **관리자 + 촬영자**를 동시에 해도 됨(다른 사업).  
UI는 `activeJoin`(촬영) / `ownedProjects[]`(관리)를 구분해 표시.

## 4. 설정 키·기본값 (앱 로컬)

`app_settings` (또는 동등 key-value). **시크릿·PIN 평문을 로그/공유 시트에 넣지 않음.**

| 키 | 타입 | 기본 | 설명 |
|----|------|------|------|
| `project_collect_enabled` | bool | `false` | 설정 섹션 노출·기능 마스터 (OFF면 QR·자동업로드 전부 비활성) |
| `device_id` | string | 최초 UUID | API·업로드자 표시용 |
| `project_join_id` | string \| null | null | 현재 참여 중 `projectId` |
| `project_join_name` | string \| null | null | 표시용 사업명 |
| `project_join_upload_code` | string \| null | null | QR의 `c` (앱 private storage) |
| `project_join_at` | number \| null | null | 연결 시각 |
| `project_auto_upload` | bool | `true` | 연결 중이면 저장 시 자동 업로드 |
| `project_wifi_only` | bool | `false` | true면 Wi-Fi에서만 업로드 |
| `project_owned_json` | string | `[]` | 관리자가 만든 사업 요약 배열 JSON |
| `project_last_inbox_fetch_at` | number \| null | null | 수신 새로고침 시각 |

**관리자 사업 요약 객체 (`project_owned_json` 요소):**

| 필드 | 설명 |
|------|------|
| `projectId` | 서버 발급 |
| `name` | 사업명 |
| `createdAt` | epoch ms |
| `expiresAt` | epoch ms |
| `uploadCode` | QR용 (기기에만) |
| `collectorPinSet` | bool — PIN 자체는 SecureStore 권장 키 `project_pin_{projectId}` |

**TTL 기본값**

| 항목 | 값 |
|------|-----|
| 기본 TTL | **7일** |
| 선택지 (만들기 UI) | 3일 / 7일 / 14일 / 30일 |
| 만료 임박 표시 | 남은 시간 &lt; 24h → 수신·QR 화면에 경고 문구 |

**자동 업로드 이미지 프로필 (UI 문구용)**  
「용량을 줄여 올립니다 (약 1024px)」— 설정에 고급 화질 옵션은 MVP에서 숨김.

### 5.0 설정 — 섹션 「사업 취합」(S0)

**위치:** 설정 스크롤 중하부 (갤러리·워터마크 근처, OSS보다 위).

| 요소 | 스펙 |
|------|------|
| 섹션 제목 | `사업 취합` |
| 설명 1줄 | `QR로 연결하면 저장 시 일시 저장소(한국)로 올립니다. 기본 꺼짐.` |
| 마스터 스위치 | `사용` / `사용 안 함` → `project_collect_enabled` |
| OFF일 때 | 하위 행 숨김 또는 disabled |
| ON + 미연결 | 행: `시작하기` → S1, 우측 쉐브론 |
| ON + 촬영 연결 | 행1: `참여 중 · {사업명}` / 보조: `자동 올리기 {ON\|OFF}` |
| | 행2: `연결 끊기` (destructive 톤) |
| ON + 관리 사업 | 행: `내 사업 · {이름}` / `QR·수신` → S3 또는 S1 |
| Wi-Fi만 | 스위치 `Wi-Fi에서만 올리기` (`project_wifi_only`) |

**연결 끊기 확인**

- 제목: `사업 연결을 끊을까요?`
- 본문: `이후 저장분은 더 이상 올라가지 않습니다. 이미 올린 항목은 관리자 수신함에 남아 있을 수 있습니다.`
- 버튼: `취소` / `끊기`

### 5.1 사업 허브 (S1)

**헤더:** `사업 취합` · 뒤로 → 설정

**본문 (세로 카드 3개, 카드는 탭 가능한 큰 행 — 장식 카드 남발 지양, 기존 목록 톤):**

| 행 | 제목 | 부제 | 동작 |
|----|------|------|------|
| A | 사업 만들기 | 관리자 · QR을 보여 줍니다 | → S2 |
| B | QR로 참여 | 촬영자 · 한 번만 연결 | → S4 |
| C | 수신 목록 | 올린 사진 확인·내 폰으로 | → S5 (관리 사업 없으면 안내) |

**하단 고정 힌트 (작은 글씨):**  
`일시 보관 후 삭제됩니다. 영구 저장소가 아닙니다.`

**관리 사업이 있을 때:** A 아래에 최근 사업 1줄 요약  
`{이름} · 남은 {n}일 · QR 보기`

**취합 엑셀 (관리 사업 1줄 아래, 선택 CTA):**

| 요소 | 스펙 |
|------|------|
| 버튼 | `취합 엑셀 보내기` |
| 활성 | 해당 사업 폴더로 **이미 가져온** 로컬 스탬프 ≥ 1 |
| 비활성·탭 시 | `아직 내 폰에 가져온 사진이 없습니다.` |
| 동작 | 해당 `groupName` 전체 → 기존 파일명 모달 → `createStampsXlsx` / 공유 |
| 기본 파일명 예 | `{사업명}_취합_{yyyyMMdd}` |

### 5.2 사업 만들기 (S2)

| 필드 | 컨트롤 | 검증 |
|------|--------|------|
| 사업 이름 | 단일 라인 TextInput, placeholder `예: 2026 여름 점검` | 1~40자, 필수 |
| 보관 기간 | 세그먼트/칩: `3일` `7일` `14일` `30일` | 기본 **7일** 선택 |
| 취합 PIN | 숫자 `SecureTextEntry`, 4~6자리 | 필수, 확인 입력 1회 더 |
| 취합 PIN 확인 | 동일 | 불일치 시 인라인 에러 |

**안내 박스 (1회성 톤):**  
`PIN은 수신·삭제에만 씁니다. QR에는 들어가지 않습니다. QR을 찍은 사람은 올리기만 할 수 있습니다.`

**1차 버튼:** `만들기` (busy 시 스피너, 중복 탭 방지)

**성공 시:** S3로 교체 진입 (뒤로로 S2 재진입 시 동일 사업 QR 재표시).

**실패:** Alert `사업을 만들지 못했습니다` + 서버 메시지 1줄.

### 5.3 관리자 QR (S3)

**레이아웃 (위에서 아래):**

1. 사업명 (제목급, 기존 설정 title 톤)
2. 남은 기간: `일시 보관 · {expiresAt}까지 (D-n)`
3. **QR 영역** — 화면 너비의 ~70%, 흰 바탕, 충분한 quiet zone (기존 `qrCodeService` 패턴 재사용 가능)
4. 코드 텍스트: `사업코드 {projectId}` / `참여코드 {uploadCode}` (등폭·복사 버튼)
5. 버튼 행:
   - `공유` — OS 공유 (딥링크 URL 또는 `voicestamp://join?...`)
   - `코드 새로고침` — uploadCode 재발급 확인 후 QR 갱신
   - `수신 목록` → S5
6. destructive 텍스트 버튼: `사업 종료` → 확인 후 close API · 로컬 owned 제거 · S1

**QR 페이로드 (표시·공유 동일):**

```text
voicestamp://join?p={projectId}&c={uploadCode}
```

폴백 공유 문장:  
`VoiceStamp 사업 참여: {name}\n{https://voicestamp-gilt.vercel.app/join?p=…&c=…}`

**밝기:** QR 화면 진입 시 화면 밝기 일시 상승(가능하면) — 현장 스캔용. 이탈 시 복구.

**보안 카피 (QR 아래 작은 글씨):**  
`이 QR은 올리기 전용입니다. PIN을 함께 보내지 마세요.`

### 5.4 QR/코드로 참여 (S4)

**탭 2개 (세그먼트):**

| 탭 | 내용 |
|----|------|
| 스캔 | 카메라 프리뷰 + 촬영 권한. 성공 시 파싱 → 확인 시트 |
| 코드 입력 | `사업코드` + `참여코드` 두 필드 · `연결` |

**스캔 성공 / 연결 직전 확인 시트 (필수 동의):**

- 제목: `{사업명}에 참여할까요?` (이름을 모르면 `이 사업`)
- 본문:
  - `연결 후 새로 저장하는 사진·메모·위치가 일시 저장소(한국)로 전송됩니다.`
  - `기본 보관 {n}일 · 관리자가 더 일찍 지울 수 있습니다.`
  - `ZIP을 보낼 필요는 없습니다.`
- 체크(또는 명시 버튼만): MVP는 **「참여하고 자동으로 올리기」** 단일 확인 버튼으로 충분
- 버튼: `취소` / `참여`

**성공:** Toast/Alert `연결되었습니다. 저장 시 자동으로 올라갑니다.` → 설정 또는 카메라로.

**이미 다른 사업 연결 중:**  
`지금 {old}에 연결되어 있습니다. {new}로 바꿀까요?` → `유지` / `바꾸기`

**딥링크:** 앱 실행 중·콜드스타트 모두 S4 확인 시트로 진입 (자동 연결 금지 — 반드시 확인).

### 5.5 수신 목록 (S5)

**헤더:** `수신` · 사업 전환(관리 사업 복수 시) · `새로고침`

**비어 있음:**  
`아직 올라온 사진이 없습니다. QR을 보여 주고 저장을 기다려 주세요.`

**리스트 행 (기존 Stamp 목록보다 단순):**

| 영역 | 내용 |
|------|------|
| 좌 | 썸네일 (presign GET 캐시) |
| 중 | 제목 · 장소/층 · 올린 시각 · (선택) 기기 짧은 id |
| 우 | 상태칩: `새 항목` / `가져옴` |

**가져오기 옵션 (시트 또는 하단 접기 — 첫 가져오기 전·설정에서 변경 가능):**

| 컨트롤 | 기본 | 설명 |
|--------|------|------|
| 가져온 뒤 일시 저장소에서 삭제 | ON | import-ack / 서버 삭제 |
| **저장 폴더 방식** | 칩 | `날짜_사업명` (기본) / `사업명만` |
| 저장 폴더 미리보기 | 읽기 전용 1줄 | 예: `20260807_여름점검` |

- `날짜_사업명`: `YYYYMMDD_{sanitize(사업명)}` — 기존 앨범·`groupName` 규칙과 맞춤  
- `사업명만`: `sanitize(사업명)`  
- 가져오기 성공 Toast: `{n}장을 「{folder}」에 저장했습니다.`  
- 동일 `stampId` 로컬 존재 시 건너뛰고 요약에 `이미 있는 항목은 건너뜀` 포함  

**하단 바 (선택 모드 — 기존 목록 보내기 바와 유사):**

| 버튼 | 동작 |
|------|------|
| 전체 선택 | |
| 내 폰으로 | 선택분 다운로드 → `persistImage` + `insertStamp` · `groupName` = 위 폴더 규칙 → 성공 시 `가져옴` · (옵션) 서버 삭제 |
| **엑셀** | **「가져옴」인 선택분만** 활성. 로컬 id로 기존 XLSX 파이프라인. 미가져오기만 선택 시 안내: `엑셀로 보내려면 먼저 「내 폰으로」를 눌러 주세요.` |
| 서버에서만 삭제 | 로컬 미반영, 중계본 삭제 |

**엑셀 UX 원칙 (단순):**  
수신함에서 바로 클라우드 바이트로 엑셀을 만들지 않는다. **로컬 import 선행** 후 기존 `exportXlsx` 재사용.

**진행:** `가져오는 중 3/12` 오버레이 (다량 시). 실패 건수 Alert.

**PIN:** 수신 API 호출 전 PIN 미저장이면 PIN 입력 모달 1회 → SecureStore.

### 5.6 저장 목록 뱃지·취합 (S6)

#### 촬영자 뱃지

`project_join_id` 있을 때만.

| `upload_status` (로컬) | 행 UI |
|------------------------|--------|
| `pending` / `uploading` | 작은 회색 점 또는 `올리는 중` |
| `synced` | 작은 체크 (무채색) |
| `failed` | `올리기 실패` 탭 → 재시도 / 무시 |

헤더 근처(선택): `사업 · {짧은이름}` 텍스트 한 줄 — 탭 시 설정 사업 섹션.

**선택 모드 보내기 바에는 MVP에서 「사업에 올리기」수동 버튼을 넣지 않음** (자동이 기본).  
고급: 실패 재시도만.

#### 관리자 — import 이후

| 요소 | 스펙 |
|------|------|
| 폴더·장소 필터 | 사업 `groupName`으로 필터 (기존 필터 재사용) |
| 빠른 선택 (선택·P2) | `이 폴더 전체 선택` — 있으면 엑셀 일괄이 쉬움 |
| 보내기 바 **엑셀** | 기존 버튼 그대로. 사업 폴더만 골라 보내면 “취합 엑셀” |
| 전용 CTA | MVP는 S1 `취합 엑셀 보내기` + S5 엑셀로 충분. 목록에 중복 버튼 추가하지 않음 |

---

### 5.7 저장 직후 (S7)

- 성공 저장 모달 닫힘 → 큐 적재 **무음**
- 셀룰러 + `wifi_only` → 대기 상태만, 토스트 없음
- 연속 실패 3회 → 1회 Alert: `사업으로 올리지 못했습니다. 목록에서 재시도할 수 있습니다.`

---

### 5.8 엑셀 취합 — 명시적 비목표

| 비목표 | 이유 |
|--------|------|
| 기존 xlsx에 행 append | 복잡도·충돌. 매번 **새 파일** |
| 클라우드에 xlsx 영구 보관 | 일시 중계 원칙과 충돌 |
| 촬영자 → 관리자 엑셀 직접 전송 | 수신→로컬→엑셀로 통일 |
| 수신함에서 미import분 즉시 엑셀 | 썸네일·경로가 로컬 `exportXlsx` 전제 |

## 13. 수용 기준 (UI)

| # | 기준 |
|---|------|
| 1 | 마스터 OFF면 자동 업로드·QR 진입 불가 |
